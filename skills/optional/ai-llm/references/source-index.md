# Source index

Research checked 2026-09-15. Links below are primary or standards-body sources. Provider documentation is evidence for the named provider/API/version only; it is not a universal guarantee. Re-check versioned pages before relying on current capability, pricing, retention, or protocol behavior.

## OpenAI API and agent documentation

- [Models](https://developers.openai.com/api/docs/models) — current model catalog, modality/tool availability, context/output information, and provider model-selection entry points. **Use for:** model boundary and compatibility checks. **Does not establish:** that a model is best for a particular workload or that catalog benchmarks predict this system's outcomes.
- [Model selection](https://developers.openai.com/api/docs/guides/model-selection) — provider guidance for choosing among models. **Use for:** recording task requirements and validating an explicit model choice. **Does not establish:** a provider-neutral routing policy or production quality threshold.
- [Prompt engineering](https://developers.openai.com/api/docs/guides/prompt-engineering) — prompt behavior is non-deterministic and can vary across model types and snapshots; documents prompting strategies. **Use for:** prompt/context design and versioned regression. **Does not establish:** prompt-only security or correctness guarantees.
- [Function calling](https://developers.openai.com/api/docs/guides/function-calling) — function tools use schemas; `tool_choice`, allowed tools, parallel calls, and strict mode are provider/API controls. **Use for:** tool boundary, schema configuration, and parallelism decisions. **Does not establish:** authorization, safe side effects, or semantic correctness.
- [Structured outputs](https://developers.openai.com/api/docs/guides/structured-outputs) — structured response formats and function-call schemas differ from JSON mode; supported schema subsets and refusal handling are documented. **Use for:** parse/validation design. **Does not establish:** truthfulness, business-rule validity, or permission to act.
- [Evals API reference](https://platform.openai.com/docs/api-reference/evals) and [Working with evals](https://developers.openai.com/api/docs/guides/evals) — evaluation data sources, graders, and evaluation runs. **Use for:** provider eval integration and grader selection. **Does not establish:** that an OpenAI eval score is sufficient for release.
- [Evaluate agent workflows](https://developers.openai.com/api/docs/guides/agent-evals) — traces capture model calls, tool calls, guardrails, and handoffs; trace grading helps find workflow regressions. **Use for:** agent workflow evidence. **Does not establish:** environment-side-effect success unless the environment is separately checked.
- [Results and state](https://developers.openai.com/api/docs/guides/agents/results) — final output, history, handoff ownership, interruptions, and resumable state surfaces. **Use for:** explicit state and continuation design. **Does not establish:** that a completed turn means every tool or external operation succeeded.
- [Run and continue sessions](https://developers.openai.com/api/docs/guides/agents-api/sessions) — session continuation, event outcomes, retrieval after disconnect, and cancellation. **Use for:** stop/recovery and state reconciliation. **Does not establish:** durable business transactions or idempotency for the application's tools.
- [Guardrails and human review](https://developers.openai.com/api/docs/guides/agents/guardrails-approvals) — automatic input/output/tool checks, approval interruptions, resumable state, and workflow-boundary considerations. **Use for:** approval and escalation paths. **Does not establish:** that agent-level checks cover every custom tool or that human review is unnecessary.
- [Retrieval](https://developers.openai.com/api/docs/guides/retrieval) — semantic search, vector stores, file chunking/embedding/indexing, metadata attributes, filtering, and storage considerations. **Use for:** RAG mechanics and freshness/cost checks. **Does not establish:** retrieval relevance, grounding, citation correctness, or ACL safety for this corpus.
- [Data controls](https://developers.openai.com/api/docs/guides/your-data) — provider statements about API data use and configurable retention controls. **Use for:** documenting the provider data-flow assumption and verifying account configuration. **Does not replace:** application minimization, access control, tenant isolation, logging restrictions, deletion processes, contractual review, or jurisdictional obligations.
- [Safety best practices](https://developers.openai.com/api/docs/guides/safety-best-practices), [Red teaming](https://developers.openai.com/api/docs/guides/red-teaming), and [Moderation](https://developers.openai.com/api/docs/guides/moderation) — moderation, adversarial testing, human review, input/output constraints, and moderation signals. **Use for:** safety test planning. **Does not establish:** complete safety, abuse prevention, or domain compliance.
- [Latency optimization](https://developers.openai.com/api/docs/guides/latency-optimization) and [Cost optimization](https://developers.openai.com/api/docs/guides/cost-optimization) — request/token reduction, model selection, parallelism, streaming, and batch/flex cost considerations. **Use for:** measured performance and budget work. **Does not establish:** an SLA or workload-specific cost/latency outcome.
- [Pricing](https://developers.openai.com/api/docs/pricing), [Prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching), [Rate limits](https://developers.openai.com/api/docs/guides/rate-limits), and [Production best practices](https://developers.openai.com/api/docs/guides/production-best-practices) — current commercial/operational controls and deployment guidance. **Use for:** live budget, capacity, and operational verification. **Does not establish:** a permanent price, quota, availability guarantee, or architecture independent of the deployed account.

## OWASP and NIST

- [OWASP GenAI LLM Top 10 2026](https://genai.owasp.org/resource/owasp-genai-llm-top-10-2026/) — latest edition found during this research, with threat descriptions, attack scenarios, mitigations, and mappings. **Use for:** threat-model coverage and security test cases. **Does not establish:** a complete threat model, risk ranking for this system, or certification.
- [OWASP Top 10 for LLM Applications 2025](https://genai.owasp.org/resource/owasp-top-10-for-llm-applications-2025/) — prior versioned edition. **Use for:** comparing versioned guidance when a project or control references 2025. **Does not establish:** that older rankings are current; pin the edition used in the threat model.
- [NIST AI Risk Management Framework 1.0](https://www.nist.gov/itl/ai-risk-management-framework) and [NIST AI RMF Playbook](https://www.nist.gov/itl/ai-risk-management-framework/nist-ai-rmf-playbook) — voluntary, use-case-agnostic risk-management framework organized around Govern, Map, Measure, and Manage. **Use for:** risk register, ownership, evidence, and lifecycle governance. **Does not establish:** legal compliance, a product safety guarantee, or mandatory thresholds.
- [NIST Generative AI Profile, NIST AI 600-1](https://doi.org/10.6028/NIST.AI.600-1) — generative-AI-specific profile for applying AI RMF concepts. **Use for:** expanding the risk register for generative-AI failure modes. **Does not establish:** controls that automatically satisfy a sector regulation or organization policy.

## Model Context Protocol (use only when MCP is in scope)

MCP pages are versioned. The links below pin the 2025-11-25 specification used for this research; record the exact version implemented and re-check the specification before release.

- [MCP Tools, 2025-11-25](https://modelcontextprotocol.io/specification/2025-11-25/server/tools) — model-controlled tools, input/output schemas, structured content, tool errors, trusted-server caveats, input/result validation, rate limits, timeouts, audit logging, and human confirmation guidance. **Use for:** MCP tool-surface review. **Does not establish:** that a client has implemented authorization or that annotations/results are trustworthy.
- [MCP Lifecycle, 2025-11-25](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle) — initialization, capability/version negotiation, operation, shutdown, and request timeout expectations. **Use for:** connection/state lifecycle and failure handling. **Does not establish:** application-level run durability, transaction semantics, or agent stop policy.
- [MCP Authorization, 2025-11-25](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization) — OAuth-based protected-resource discovery, resource indicators, token audience validation, PKCE, secure token handling, and the prohibition on token passthrough. **Use for:** HTTP MCP authorization review. **Does not establish:** authorization for stdio deployments, downstream business permissions, or the application's complete identity model.
- [MCP Architecture, 2025-06-18](https://modelcontextprotocol.io/specification/2025-06-18/architecture) — host/client/server separation and resources, prompts, and tools as protocol primitives. **Use for:** protocol boundary terminology. **Does not establish:** a universal agent architecture or deployment standard.

## Evidence map

| Concern | Primary sources | Engineering synthesis required |
| --- | --- | --- |
| Model boundary and prompt/context | OpenAI Models, Model selection, Prompt engineering | Pin versions, separate trusted instructions from data, and measure the chosen model on the real task. |
| Schema and parsing | OpenAI Structured outputs, Function calling; MCP Tools when applicable | Parse and validate locally; add semantic/business checks; handle refusal, truncation, and unsupported schemas. |
| Tools and permissions | OpenAI Function calling, Guardrails and human review; MCP Tools and Authorization when applicable | Keep authorization and side-effect policy in the executor; use least privilege, approval, idempotency, timeout, and audit. |
| RAG and grounding | OpenAI Retrieval | Measure retrieval, ACL/freshness, grounding, citations, answer quality, latency, and cost as separate properties. |
| Agent state and recovery | OpenAI Results and state, Sessions, Guardrails; MCP Lifecycle when applicable | Use a durable explicit state machine with budgets, stop reasons, checkpoint/reconcile, and ownership. |
| Evals and regression | OpenAI Evals, Agent evals, Safety/Red teaming | Version datasets/configuration, use deterministic and calibrated graders, inspect slices, and gate releases on severe failures. |
| Safety and governance | OWASP LLM Top 10, NIST AI RMF/GenAI Profile, OpenAI Safety/Moderation | Map threats to data flows and controls; assign owners; document residual risk and escalation. |
| Privacy and data handling | OpenAI Data controls; NIST AI RMF | Verify account/provider settings but retain application-level minimization, access, retention, and deletion controls. |
| Latency and cost | OpenAI Latency, Cost, Pricing, Prompt caching, Rate limits | Instrument the full path and optimize only against measured quality, safety, latency, and cost trade-offs. |
| Environment-outcome evidence | OpenAI Sessions/Results and state, Agent evals; MCP Tools when applicable | Separate transcript claims from trace evidence and authoritative postcondition checks in the source system. |

## Limitations and freshness

- This index records source locations and their decision-relevant scope; it intentionally does not reproduce provider manuals or OWASP/NIST text.
- OpenAI model IDs, supported features, defaults, prices, retention options, quotas, and SDK/API surfaces can change. Treat all such details as time- and account-sensitive.
- MCP requirements depend on the selected version and transport. Do not apply an HTTP authorization statement to stdio without checking the specification and deployment.
- OWASP is awareness and threat-model guidance, not a complete control catalog. NIST AI RMF is voluntary and does not certify a system.
- No linked source proves that an application is correct, secure, private, compliant, autonomous, or production-ready. Those claims require system-specific measured evidence.
